# Quote Generator — Design Spec

**Date**: 2026-05-04
**Owner**: soul2fade (The Bench COO / Automated COO)
**Status**: Approved, ready for implementation plan

## 1. Overview

A public-facing demo of an AI-powered quote generator for trades contractors in the Sacramento metro area. The visitor types a job description in plain English, picks their trade, and the tool produces a customer-ready quote document complete with line items, totals, terms, and signature block. The demo doubles as a portfolio piece (lives on LinkedIn Featured) and a sales tool (CTAs to a Calendly booking).

This is the second tool in a planned family of contractor tools, the first being the existing dashboard demo at `automated-coo-demo.netlify.app`. A future "Contractor OS" wrapper may unify them; that decision is deferred.

## 2. Goals & non-goals

### Goals
- Demonstrate convincingly that AI can take an unstructured job description and produce a structured, regionally-accurate, customer-ready quote
- Be visually consistent with the existing dashboard demo so the two pieces feel like a coherent portfolio
- Ship as a separate repo + Netlify deploy that can be combined with the dashboard later if/when desired
- Cap ongoing API costs at well under $20/year through prudent model choice (Haiku) and a hybrid demo flow that defers live calls to engaged visitors

### Non-goals (v1)
- Saved history of generated quotes
- True PDF export (browser print-to-PDF is sufficient)
- Customer email / send / e-signature
- Conversion of a quote into an invoice (that's the second planned tool)
- Voice input
- Real authentication, multi-tenancy, or persistent customer database
- Multi-page jobs, change orders, or revision tracking
- Image uploads of the job site
- Anything related to scheduling, dispatch, or job follow-up

- **Streaming**: Server-Sent Events (SSE) from the Netlify function back to the client

### Visual design DNA
- Same color palette as the dashboard (slate-50 page background, navy/blue brand accents)
- Same typography (default Tailwind sans-serif, comfortable line height)
- Same card / border patterns (rounded-2xl, subtle border, soft shadow)
- Quote document itself uses a more "document-like" internal style (serif headers, structured table, ample whitespace) but the page chrome (header, controls, footer) matches the dashboard

## 4. UX flow

### Page layout (top to bottom)
1. **Header** — brand mark, headline: *"AI quote generator for trades. Type the job — get a customer-ready quote."*
2. **Trade toggle** — 4 buttons (HVAC / Plumbing / Electrical / Roofing), styled to match the dashboard's industry switcher
3. **Input area** — textarea with per-trade placeholder text (e.g., HVAC: *"Homeowner needs full system replacement, 2200 sq ft single-story…"*), a **Generate Quote** button
4. **Output area** — a polished quote document (see section 5), pre-rendered with a canned example for the selected trade on initial page load
5. **CTA banner** — *"Want this for your business? Book a 20-min consult →"* linking to `https://cal.com/benchcoo/20min`
6. **Footer** — *"Generated by The Automated COO"* link back to the dashboard / main site

### Interaction states

**On page load:**
- Selected trade defaults to HVAC
- A pre-baked canned quote for HVAC is already rendered in the output area — visitors see a real quote document within ~1 second of landing
- Textarea is empty with placeholder text inviting custom input

**On trade toggle click:**
- Output area immediately swaps to that trade's canned example
- Textarea placeholder updates to the new trade
- Any in-progress generation is cancelled (abort the SSE stream)

**On Generate Quote click (with non-empty textarea):**
- Button enters loading state ("Analyzing job…" with spinner)
- Output area transitions: existing canned example fades, new quote streams in
- Document renders progressively as JSON arrives: header → customer block → line items appearing row-by-row → totals → terms
- Total perceived time is short because there's continuous on-screen activity (typical 3–5 seconds end-to-end with Haiku + streaming)
- On completion, button returns to default state

**On error (API failure, timeout, malformed output):**
- Output area falls back to the canned example for the current trade
- Small toast at bottom: *"Couldn't generate live — showing a sample instead. Try again?"*
- Button returns to default state

### Print mode
- A small "Print quote" button at the top right of the output area calls `window.print()`
- Print CSS hides page chrome (header, toggle, textarea, CTA, footer) so only the quote document prints
- Visitor uses browser's "Save as PDF" if they want a file

## 5. Quote document structure

The rendered quote document, top to bottom:

1. **Letterhead**
   - Contractor name (fictitious, per-trade Sacramento-flavored — see naming below)
   - CSLB-format contractor license number (e.g., "CSLB Lic. #1098765")
   - Address (a plausible Sacramento-area address)
   - Phone, email, website

2. **Quote metadata block** (right side of letterhead)
   - Quote number (auto-generated, e.g., `Q-2026-0142`)
   - Date issued (today)
   - Valid until (today + 30 days)

3. **Customer info block**
   - Auto-populated with realistic sample data (e.g., *"Diana Chen, 4421 J St, Sacramento, CA 95819, dchen@example.com"*)
   - Inline-editable: visitor can click any field to overwrite
   - Edits do not trigger AI re-generation; they're cosmetic

4. **Job summary**
   - 1–2 paragraphs the AI rephrases professionally from the visitor's job description input
   - For canned examples, this is pre-written

5. **Line items table**
   - Two visually-distinct sections: Labor and Materials
   - Columns: Description / Qty / Unit / Unit Price / Total
   - Each line item is one row

6. **Totals block**
   - Subtotal
   - Sacramento County sales tax (7.75%) — applied only to materials, not labor (correct for California)
   - Grand total

7. **Terms & conditions**
   - 4–5 standard contractor terms: deposit required, change orders in writing, warranty period, payment due timing, scope exclusions
   - Same boilerplate across trades

8. **Acceptance block**
   - Customer signature line
   - Date line
   - Optional accepted-by line

9. **Footer attribution**
   - *"Generated by The Automated COO"* with link to the user's portfolio site

### Placeholder contractor names per trade

| Trade | Name |
|---|---|
| HVAC | Your HVAC Company |
| Plumbing | Your Plumbing Company |
| Electrical | Your Electrical Company |
| Roofing | Your Roofing Company |

These are deliberately generic so visitors mentally substitute their own business name (the demo's pitch is "this is what *your* quotes could look like"). Avoiding any real or invented company name also sidesteps trademark or look-alike issues with actual Sacramento-area contractors. License numbers shown follow CSLB formatting but are placeholder strings (e.g., `Lic. #SAMPLE`). Footer attribution makes clear this is a demo.

## 6. AI integration

### Endpoint
**Netlify function**: `POST /api/quote`

**Request body:**
```ts
{
  trade: 'hvac' | 'plumbing' | 'electrical' | 'roofing';
  description: string;
}
```

**Response**: Server-Sent Events stream of JSON chunks. Final assembled object matches the quote schema.

### System prompt assembly

The system prompt is dynamically assembled per request from four parts:

1. **Identity / role**
   *"You are an expert quote estimator for {trade} contractors operating in the Sacramento, CA metropolitan statistical area. You produce realistic, regionally-accurate quotes from plain-English job descriptions."*

2. **Sacramento pricing reference** (injected from `src/pricing/sacramento.ts`, see section 7)
   Per-trade labor rates, common materials with markups, typical job-size ranges, sales tax rate, and regional notes.

3. **Output schema constraint**
   *"Respond with strict JSON matching this schema: { summary, lineItems: [...], terms: [...], subtotal, tax, total, validUntil }. Do not include prose before or after the JSON."*

4. **Quality constraints**
   *"All prices must reflect Sacramento MSA norms from the pricing reference above. Use realistic quantities. Separate labor from materials. Apply sales tax to materials only. Use 30-day validity from today."*

### User message
The visitor's raw job description, with the selected trade prepended for clarity:
> *"Trade: HVAC. Job description: {visitor's text}"*

### Streaming
- Anthropic SDK `messages.stream()` mode
- Server-side: function pipes Anthropic's stream through to the HTTP response as SSE events
- Client-side: an `EventSource`-style consumer parses partial JSON as it arrives, using a streaming JSON parser (e.g., `partial-json`)
- Document fields populate progressively as their JSON keys complete

### Error handling
- 30-second timeout on the upstream Anthropic call
- On timeout, rate limit, network error, or malformed JSON: fall back to the trade's canned example with a toast message
- Errors are logged server-side (Netlify function logs) but never surfaced verbatim to the client

### Cost expectations
Haiku 4.5 pricing as of 2026-05-04: ~$0.001 per 1k input tokens, ~$0.005 per 1k output tokens. A typical quote generation: ~2k input tokens (system + user), ~1k output tokens → ~$0.007 per call. At 500 visitors/year with maybe 30% trying live generation, expected annual cost is ~$1–3. Comfortably under the $20/year cap.

### Source of values
A quick research pass before implementation against current 2026 Sacramento-area sources (BLS California regional data, RSMeans regional indices, local trade association posts). Values are baked in for v1; they don't need to be perfect, just defensible. A clear comment block in the file documents the source date so future updates are easy.

## 8. Open questions

- **Toggle visual placement**: should the trade toggle live above the input or above the output? Recommended: above input, since trade is conceptually a property of the job being described. To be confirmed during implementation when the layout is real.
- **Sample customer data**: should sample customer names rotate (different sample for each trade), or stay the same? Recommended: rotate per trade for variety.
- **Print CSS detail**: how much polish in the print stylesheet? Recommended: enough that print-to-PDF produces something clean, not perfect typesetting. v1 acceptable bar is "looks like a real quote when printed."

## 9. Risks & mitigations

| Risk | Mitigation |
|---|---|
| AI returns malformed JSON | Try-parse; on failure, fall back to canned example with toast |
| Anthropic API outage | Same fallback; canned examples always available |
| Sacramento pricing data feels off | Document source date in pricing file; refine based on user feedback |
| Demo gets viral attention and API costs spike | Set monthly Anthropic spend limit in their dashboard; canned-first flow already throttles cost |
| Visitor types something offensive / non-job content | System prompt instructs the model to politely refuse and ask for a job description. Visitor input does transit Anthropic's API; we don't persist it server-side, so no database leakage path exists |

## 10. Success criteria

- Live at `automated-quotes-demo.netlify.app` with the four-trade toggle working
- Canned example renders within 1 second of page load for each trade
- Live AI generation completes within 8 seconds for typical job descriptions, with streaming progress
- Print-to-PDF produces a clean, standalone quote document
- Visual cohesion with `automated-coo-demo.netlify.app` is obvious to anyone visiting both
- LinkedIn Post Inspector renders a proper preview card with OG image
